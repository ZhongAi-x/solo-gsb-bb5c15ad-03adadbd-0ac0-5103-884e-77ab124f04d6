# 编织逐行针数校验与线材用量估算

输入尺码与起针数、每行编织指令，逐行推算消耗/产出针数：每个尺码独立地以上一行的
产出作为下一行的可用针数；某尺码针数不足或超出时仅停止该尺码，其余尺码继续推算。
页面并排展示各尺码的有效行、首个错误与最终针数；指令本身非法（含倍数项数与尺码数
不符）时报原文行号与字符位置。也提供单尺码校验接口。

多尺码校验同时支持线材用量估算：给出 `k`、`p`、`yo`、`k2tog` 的单个记号克重、
损耗百分比与每团克重后，按每个尺码每行各记号的实际出现次数（嵌套重复与按尺码重复
均计入）累计原始克重，返回每行累计克重、原始总量、含损耗总量与向上取整的线团数。
某尺码遇针数错误停止后续行（或出现让全部尺码停止的语法错误）时，该尺码的用量标记
为**部分估算**（`partial: true`）。

多尺码校验还会在针数出现差额时，针对首个出错行给出**倍数修正建议**：逐一尝试只改
该行一个现有的 `*n` 或 `*{...}` 倍数（嵌套重复只按算术推导、不展开），找到让本行
所有尚在推算的尺码消耗恰好等于各自可用针数的改法（倍数仍为正整数，原本正确的尺码
不受影响），并在页面上支持一键替换后重新校验。

尺码列表支持**上移、下移**：移动时按尺码原顺序建立映射，同步重排指令中每一处
`*{a|b|c}` 的倍数项（嵌套重复、同一行多处均生效），普通 `*n` 及其他原文保持不变。
若任一按尺码倍数的项数或数值不合法，**整次移动不生效**，并提示原文行号与字符位置。
重排只是把同一尺码的倍数搬到新位置，因此各尺码重新校验的针数与移动前完全一致。

页面还提供**单行针位预览**：选择图解原文行、尺码与起始操作序号，即按所选尺码定位
嵌套重复与 `*{a|b|c}` 倍数，逐针显示最多 50 个实际针法、每个针法消耗的入针范围
（如第 3–4 针）与产出的出针序号，支持上一页/下一页及首页/尾页、按序号跳转；
`yo` 等零入针针法不显示入针范围，而是标明其插入位置（行首或第几针之后）。定位
只做算术并整段跳过未显示的重复，**不展开整行**，`(k)*1000000000` 的尾段也能直接
查看。非法行返回与校验相同的语法错误与原文行号、字符位置，不提供部分预览。

此外提供**跨行针位追踪**：选定一个尺码与一枚起针序号（起针中的第 n 针），即按
**原文行号**逐行列出这枚针在每个有效行被哪种针法消耗、该操作的**入针范围**与
**产出针位**（产出针位自动作为下一行的入针序号）；遇 `k2tog` 标明它与相邻的哪
一枚针**合并**，`yo` 不消耗入针、只会把之后的产出位置推后。嵌套重复与 `*{...}`
按所选尺码算术定位，**不展开十亿次重复**。起针序号超出该尺码起针数时明确报错；
该尺码针数不符或任一行语法错误时停在首个错误行、保留此前轨迹，并给出原文行号与
字符位置（语法错误时）。

页面最下方是独立的**多尺码对称花样排针**模块：输入每 10 厘米针数、按从小到大
排列的各尺码目标片幅、单侧边针数、中央针数、花样宽度（针）与允许宽差，为全部
尺码选择**严格递增**的单侧花样重复数。每侧使用相同且至少一次的完整花样重复：
`起针数 = 2×边针 + 中央针 + 2×花样宽度×单侧重复数`，
`实际片幅 = 起针数 × 10 ÷ 每10厘米针数`。要求各尺码实际片幅与目标片幅之差不
超过允许宽差，并在此前提下**最小化宽差绝对值之和**（同分取按尺码顺序字典序
最小的重复数组）；结果展示各尺码的重复数、起针数、实际片幅与偏差。无可行组合
时明确说明无法同时满足约束，并列出各尺码在允许宽差内的可行重复数范围。寻优
全程用分数精确计算（不用浮点比较宽差）。

页面最下方另有独立的**对称减针行程**模块：输入起针数、目标针数、总行数与每个
减针行单侧最多减针数（1 或 2），用**动态规划**逐行安排左右相同的减针数——
减针行之间至少隔一行平织，末行余针恰好等于目标针数。在满足约束的方案中，
**最小化各行累计减针数与线性目标进度**（总减针数×行号÷总行数）**的平方偏差
之和**，同分取逐行单侧减针数组字典序最小的方案；结果以逐行左右减针、余针表
展示（含累计减针与目标进度）。无解时说明**最多可减针数及原因**（目标针数比
起针数多、差为奇数、或行数不够）。寻优全程用分数精确计算。

页面最下方还有独立的**条纹用线排程**模块：输入总行数（1~40）、按顺序填写
2~3 种颜色的名称及各自可编织行数（库存）、最短与最长条纹行数（1~6）和偏好
段长，用**分层动态规划**求**恰好覆盖总行数**的连续条纹——每段长度都在
最短~最长区间内、相邻两段颜色不同、各色用量不超过库存；在可行方案中
**最小化各段长度与偏好段长的绝对差之和**，同分逐段按**颜色输入顺序**
（先填的颜色优先）**及段长升序**选择。结果以条纹示意条、逐段表（每段起止行、
颜色、本段用量、与偏好段长之差）与各色库存/用量/余量展示；**无解时明确提示
原因（库存合计不足或区间/异色/库存约束下无法凑成总行数），不返回部分安排**。

## 指令语法

| 记号 | 含义 | 消耗 | 产出 |
| ---- | ---- | ---- | ---- |
| `k` | 下针 | 1 | 1 |
| `p` | 上针 | 1 | 1 |
| `yo` | 挂线 | 0 | 1 |
| `k2tog` | 两针并一针 | 2 | 1 |
| `(序列)*n` | 括号序列重复 n 次，可嵌套，对所有尺码生效 | 累加 ×n | 累加 ×n |
| `(序列)*{a\|b\|c}` | 按尺码分别取倍数：竖线分隔的正整数按尺码顺序一一对应 | 累加 ×各自倍数 | 累加 ×各自倍数 |

- 记号大小写不敏感，可用空格或逗号分隔，单个记号后也可直接跟 `*n` 或 `*{a|b|c}`
  （如 `k*6`、`k*{6|8|10}`），两种重复可互相嵌套（如 `(k*{2|3} yo)*2`）。
- 倍数必须为正整数；`*0`、负数、缺失倍数都会被拒绝。
- `*{a|b|c}` 的项数必须与尺码个数一致，否则报错并指出原文行号与字符位置。
- 非法记号（如 `ssk`、`k3`）、括号不匹配、空括号都会被拒绝并指出位置。
- 解析只做算术累计，不展开重复项，`(k)*1000000000` 也能瞬间完成。

多尺码示例（尺码 S/M/L，起针 12/16/20，最终各剩 3/4/5 针）：

```text
(k2tog yo)*{6|8|10}
p*{12|16|20}
(k2tog)*{6|8|10}
(k2tog)*{3|4|5}
k*{3|4|5}
```

## 启动方式

沿用现有 Dockerfile 与 docker-compose.yml，一条命令即可启动（自动安装依赖并
构建），启动后浏览器访问 <http://localhost:8000>：

```bash
docker compose up --build
```

### 仅 Docker

```bash
docker build -t knit-check .
docker run --rm -p 8000:8000 knit-check
```

### 本地运行

```bash
pip install -r requirements.txt
python app.py            # 开发方式，默认监听 http://localhost:8000
# 或：gunicorn --bind 0.0.0.0:8000 app:app
```

## API

### 多尺码校验 `POST /api/validate-sizes`

请求体 JSON（`sizes` 按顺序给出尺码名与起针数，`*{...}` 依此顺序取值）：

```json
{
  "sizes": [
    {"name": "S", "cast_on": 12},
    {"name": "M", "cast_on": 16},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{6|8|10}\np*{12|16|20}\n(k2tog)*{6|8|10}"
}
```

响应：`sizes` 中每个尺码独立返回有效行 `rows`、首个错误 `error` 与最终针数
`final`（最后一行有效推算后的针数）；`ok` 为全部尺码是否都通过。

```json
{
  "ok": true,
  "sizes": [
    {
      "name": "S", "cast_on": 12, "ok": true,
      "rows": [{"line": 1, "instruction": "(k2tog yo)*{6|8|10}", "in": 12, "consume": 12, "produce": 12, "out": 12}],
      "error": null, "final": 6
    }
  ]
}
```

- 某尺码针数出现差额时仅该尺码停止，`error` 形如
  `{"line": 2, "type": "count", "diff": -1, "message": "...还剩 1 针未使用"}`，
  其余尺码继续推算。
- 指令无法解析（含 `*{a|b}` 项数与尺码数不符、倍数非法）时所有尺码一并停止，
  `error` 形如 `{"line": 2, "type": "parse", "char": 2, "message": "...项数不符..."}`，
  其中 `line` 为原文行号、`char` 为字符位置（均从 1 计）。
- 尺码列表非法时返回 `{"ok": false, "sizes": [], "error": {"type": "sizes", ...}}`。

#### 错误行的倍数修正建议（顶层 `suggestion`）

某行可解析、但至少一个尚在推算的尺码在该行出现针数差额时，接口会针对**首个这样的
行**逐一尝试“仅修改该行一个现有的 `*n` 或 `*{...}` 倍数”。推导只做算术：整行消耗
关于任一倍数都是“基数 + 系数 × 倍数”的线性关系，用 `*1`、`*2` 两次试算即可求出
系数（嵌套重复同样不展开），再为每个尺码解出需要的倍数。可行的建议必须同时满足：

- 本行**所有尚在推算的尺码**消耗恰好等于各自可用针数；
- 原本正确的尺码保持正确（其倍数与消耗均不变），已停止推算的尺码倍数保持原值；
- 改后的倍数均为**正整数**。

各尺码需要的新倍数相同时，建议写作普通 `*n`；不同则写作 `*{a|b|c}`（普通 `*n` 也
可能被改写成 `*{...}` 以分别满足各尺码）。候选按 **改动的尺码项数 → 倍数变化总量
→ 原文位置** 升序排列，响应只带回首条；没有针数差额或找不到可行改法时为 `null`：

```json
{
  "ok": false,
  "sizes": [ "…各尺码原有结果字段保持不变…" ],
  "suggestion": {
    "line": 1,
    "char": 11,
    "old": "*{6|8|9}",
    "new": "*{6|8|10}",
    "instruction": "(k2tog yo)*{6|8|10}",
    "produces": [12, 16, 20]
  }
}
```

| 字段 | 含义 |
| ---- | ---- |
| `line` / `char` | 出错行号与所改倍数 `*` 的字符位置（均从 1 计） |
| `old` / `new` | 被修改的倍数原文与替换后的倍数 |
| `instruction` | 替换后的整行原文（一键替换即用它替换原文对应行） |
| `produces` | 替换后该行各尺码的产出针数（按请求中尺码顺序） |

页面操作：建议显示在错误行所在尺码卡片的错误信息下方，列出改动、替换后原文与各尺码
产出；点击 **“应用并重新校验”** 会用建议行替换输入框中对应行并自动重新校验。首个
错误行修正后，若后续行仍有差额，会再次给出下一条建议，逐行迭代即可。`suggestion`
只附加在 `/api/validate-sizes` 响应顶层，不改变任何原有结果字段；单尺码接口
`/api/validate` 不返回该字段。

#### 线材用量估算（可选 `yarn`）

请求体中附带 `yarn` 对象即可同时估算用量：`k`/`p`/`yo`/`k2tog` 为各记号的单个
记号克重（非负数），`waste_percent` 为损耗百分比（非负），`grams_per_ball` 为
每团克重（必须大于 0）；数值接受数字或纯数字字符串，布尔值、负数与无法解析的
内容会被拒绝（`error.type` 为 `"yarn"`）。

```json
{
  "sizes": [
    {"name": "S", "cast_on": 12},
    {"name": "M", "cast_on": 16},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{6|8|10}\np*{12|16|20}\n(k2tog)*{6|8|10}",
  "yarn": {"k": 0.5, "p": 0.5, "yo": 0.2, "k2tog": 1.0,
           "waste_percent": 10, "grams_per_ball": 50}
}
```

每个有效行额外返回该尺码截至该行的累计克重 `weight`；每个尺码额外返回 `yarn`：

```json
{
  "name": "S", "cast_on": 12, "ok": true,
  "rows": [
    {"line": 1, "instruction": "(k2tog yo)*{6|8|10}", "in": 12,
     "consume": 12, "produce": 12, "out": 12, "weight": 7.2}
  ],
  "error": null, "final": 6,
  "yarn": {
    "raw_total": 19.2,
    "with_waste": 21.12,
    "balls": 1,
    "partial": false,
    "complete": true,
    "waste_percent": 10,
    "grams_per_ball": 50
  }
}
```

计算规则：

- 某行原始克重 = Σ（该行该尺码各记号实际次数 × 单记号克重）；嵌套 `(…)*n` 与
  按尺码的 `*{a|b|c}` 都按实际倍数算术累计，不展开重复项。
- `raw_total`：全部有效行的原始克重累计（保留两位小数）。
- `with_waste = raw_total × (1 + waste_percent/100)`（保留两位小数）。
- `balls = ceil(with_waste / grams_per_ball)`，按未四舍五入的精确含损耗值计算。
- `partial`：该尺码是否为部分估算。针数错误仅停止该尺码，其 `partial` 为
  `true`、其余尺码继续完整估算；语法错误使所有尺码停止，全部 `partial` 为
  `true`。`complete` 是其相反值。
- 不传 `yarn` 时响应不包含 `weight` 与 `yarn` 字段（其余字段不变）。

### 单尺码校验 `POST /api/validate`

请求体 JSON：

```json
{"cast_on": 12, "pattern": "(k2tog yo)*6\np*12"}
```

响应：

```json
{
  "ok": true,
  "rows": [
    {"line": 1, "instruction": "(k2tog yo)*6", "in": 12, "consume": 12, "produce": 12, "out": 12}
  ],
  "error": null,
  "final": 12
}
```

出错时 `error` 形如 `{"line": 2, "type": "count", "diff": 1, "message": "...缺少 1 针"}`
（`type` 为 `parse` / `count` / `cast_on`，解析错误另带 `char` 字符位置），
`rows` 只包含错误行之前的有效行。

### 尺码上移/下移 `POST /api/move-size`

页面上每个尺码行右侧的 **`↑`（上移）/ `↓`（下移）** 按钮调用此接口：交换相邻两个
尺码的位置，并按新尺码顺序同步重排指令原文。

请求体 JSON：`index` 为要移动的尺码下标（从 0 计），`direction` 为 `"up"` 或
`"down"`。

```json
{
  "sizes": [
    {"name": "S", "cast_on": 12},
    {"name": "M", "cast_on": 16},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{6|8|10}\np*{12|16|20}",
  "index": 0,
  "direction": "down"
}
```

成功响应返回重排后的尺码列表与指令原文（上例把 S 与 M 交换，倍数项随之交换）：

```json
{
  "ok": true,
  "sizes": [
    {"name": "M", "cast_on": 16},
    {"name": "S", "cast_on": 12},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{8|6|10}\np*{16|12|20}"
}
```

重排规则：

- 按尺码**原顺序建立映射**：移动后第 i 个位置的尺码取自移动前的某个位置，每一处
  `*{a|b|c}` 的数值都按同一映射搬移（数字原文整体搬移，空白与 `|` 等格式保留）。
- **嵌套重复与同一行多处** `*{...}` 全部同步重排；普通 `*n` 及其他原文逐字节不变，
  换行符（含 `\r\n`）、空行与行尾换行也保留。
- 若任一 `*{...}` 的**项数与尺码数不符或数值非法**（`0`、缺值、无法识别的字符、
  括号未闭合等），整次移动不生效（响应不含 `sizes`/`pattern`，页面也不改写输入），
  错误形如 `{"ok": false, "error": {"line": 2, "char": 2, "type": "reorder",
  "message": "..."}}`，其中 `line` 为原文行号、`char` 为字符位置（均从 1 计）。
- 尺码列表非法返回 `error.type` 为 `"sizes"`；已在首/末行仍继续上/下移或方向非法时
  返回 `"move"`。
- 倍数只是随尺码搬移，**重排后各尺码重新校验的针数与移动前一致**。页面在移动成功后
  会自动重新校验并并排刷新结果。

### 单行针位预览 `POST /api/preview-row`

选择图解原文行、尺码与起始操作序号，返回该尺码下从该序号起的一页（最多 50 个）
实际针法。请求沿用多尺码校验的 `sizes` 与 `pattern` 输入及同一套解析语法：

| 字段 | 含义 |
| ---- | ---- |
| `line` | 图解原文行号（从 1 计，空行计入行号但不可预览） |
| `size_index` | 尺码下标（从 0 计，对应 `sizes` 顺序，`*{...}` 按该尺码取值） |
| `start` | 起始操作序号（从 1 计，默认 1；一页最多 50 个） |

```json
{
  "sizes": [
    {"name": "S", "cast_on": 12},
    {"name": "M", "cast_on": 16},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{6|8|10}\np*{12|16|20}",
  "line": 1,
  "size_index": 0,
  "start": 1
}
```

成功响应：

```json
{
  "ok": true,
  "line": 1,
  "instruction": "(k2tog yo)*{6|8|10}",
  "size": "S",
  "size_index": 0,
  "cast_on": 12,
  "total": 12,
  "start": 1,
  "limit": 50,
  "consume": 12,
  "produce": 12,
  "items": [
    {"seq": 1, "stitch": "k2tog", "consume_before": 0, "in_from": 1, "in_to": 2, "out": 1},
    {"seq": 2, "stitch": "yo", "consume_before": 2, "in_from": null, "in_to": null, "out": 2}
  ],
  "prev_start": 1,
  "next_start": null
}
```

字段说明：

- `total`：该行在所选尺码下的实际针法总数（嵌套重复与按尺码倍数均已定位）。
- `items[].seq`：操作序号（1 起，跨页连续）；`stitch` 为 `k`/`p`/`yo`/`k2tog`。
- `in_from`/`in_to`：该针法消耗的入针范围（两端都包含）；`yo` 等零入针针法为
  `null`，其插入位置可由 `consume_before`（该针法之前已消耗的针数；0 表示行首）
  判定。每个针法恰好产出 1 针，故 `out`（产出的出针序号）等于 `seq`。
- `prev_start`/`next_start`：上一页/下一页的起始序号；已是首页/尾页时分别为
  `1`/`null`。把其中之一作为下次请求的 `start` 即可翻页。
- `consume`/`produce`：整行（所选尺码下）的消耗与产出针数，与
  `/api/validate-sizes` 该行的算术结果一致。

定位规则：嵌套重复与按尺码倍数按 `size_index` 指定的尺码算术定位，每个重复段先
计算长度再用除法跳过未显示的整段副本，**不展开整行**，因此
`(k yo)*1000000000`（共 20 亿个针法）直接请求尾段也能瞬间返回。

非法请求：

- 指令行无法解析时，`error` 与校验接口完全一致：
  `{"line": 2, "type": "parse", "char": 1, "message": "..."}`，响应不含 `items`，
  **不返回部分预览**。
- 空行或行号越界：`error.type` 为 `"line"`；尺码下标越界为 `"size_index"`；
  `start` 非正整数为 `"start"`。
- `start` 超出实际针法总数时返回
  `{"type": "start", "total": 12, "message": "...本行共 12 个实际针法"}`。
- 尺码列表非法时返回 `{"type": "sizes", ...}`。

预览只按语法定位并返回该行自身的消耗/产出，**不要求该行针数与起针数平衡**：
针数差额是校验接口的语义，不影响预览。

### 跨行针位追踪 `POST /api/track-stitch`

选择尺码与一枚起针序号，按**原文行号**逐行追踪这枚针在每个有效行被哪种针法
消耗、该操作的入针范围与产出针位。请求同样沿用多尺码校验的 `sizes` 与
`pattern` 输入及同一套解析语法：

| 字段 | 含义 |
| ---- | ---- |
| `size_index` | 尺码下标（从 0 计，默认 0，`*{...}` 按该尺码取值） |
| `needle` | 起针序号（从 1 计）：第 1 行开始前该尺码起针中的第 `needle` 枚针 |

```json
{
  "sizes": [
    {"name": "S", "cast_on": 12},
    {"name": "M", "cast_on": 16},
    {"name": "L", "cast_on": 20}
  ],
  "pattern": "(k2tog yo)*{6|8|10}\np*{12|16|20}\n(k2tog)*{6|8|10}",
  "size_index": 0,
  "needle": 12
}
```

成功响应（`tracks` 按原文行号只列**有效行**，空行计入行号但不列出）：

```json
{
  "ok": true,
  "size": "S",
  "size_index": 0,
  "cast_on": 12,
  "needle": 12,
  "tracks": [
    {"line": 1, "instruction": "(k2tog yo)*{6|8|10}", "in": 12,
     "needle_in": 12, "stitch": "k2tog", "in_from": 11, "in_to": 12,
     "merged_with": 11, "yos_before": 5, "seq": 11, "out_needle": 11,
     "consume": 12, "produce": 12, "available_out": 12},
    {"line": 2, "instruction": "p*{12|16|20}", "in": 12,
     "needle_in": 11, "stitch": "p", "in_from": 11, "in_to": 11,
     "merged_with": null, "yos_before": 0, "seq": 11, "out_needle": 11,
     "consume": 12, "produce": 12, "available_out": 12},
    {"line": 3, "instruction": "(k2tog)*{6|8|10}", "in": 12,
     "needle_in": 11, "stitch": "k2tog", "in_from": 11, "in_to": 12,
     "merged_with": 12, "yos_before": 0, "seq": 6, "out_needle": 6,
     "consume": 12, "produce": 6, "available_out": 6}
  ],
  "error": null,
  "final_needle": 6
}
```

每行字段：

- `needle_in`：这枚针在本行开始时的入针序号（等于上一行的 `out_needle`，
  第 1 行即请求的 `needle`）。
- `stitch`：实际消耗它的针法（`k`/`p`/`k2tog`；`yo` 不消耗入针，故绝不会
  作为追踪结果出现）。
- `in_from`/`in_to`：该操作的入针范围（两端都包含），`needle_in` 必在其中。
- `merged_with`：`k2tog` 与相邻针合并时给出被并入的另一枚针序号；`k`/`p`
  为 `null`。
- `seq`：该针法在本行实际针法序列中的操作序号；`yos_before` 为它之前出现
  的 `yo` 数。每个针法（含 `yo`）恰好产出 1 针，故 `out_needle = seq`：
  `yo` 不消耗入针，却占一个产出序号，只影响**之后**的位置。
- `consume`/`produce`/`available_out`：本行（所选尺码下）的消耗、产出与行
  末可用针数，与 `/api/validate-sizes` 的算术结果一致。
- `final_needle`：最后一个有效行之后这枚针的针位（仅 `ok` 为真时返回）。

定位规则与单行预览相同：嵌套重复与按尺码倍数按所选尺码算术定位，每个重复段
先求一段消耗再用除法跳过整段副本，**不展开整行**，
`(k yo)*1000000000` 中的针也能瞬间定位。

非法请求与停止规则（与逐行校验复用同一套解析与校验）：

- 起针序号超出所选尺码起针数：`error.type` 为 `"needle"`，响应带
  `cast_on` 与 `needle`，在解析任何行**之前**报错（不含 `tracks`）；序号非
  正整数同样为 `"needle"`。
- 该尺码针数不符：停在首个差额行，`error.type` 为 `"count"`（带
  `available`/`consume`/`diff`），`tracks` 保留此前各有效行轨迹。
- 任一行语法错误：停在首个错误行，`error.type` 为 `"parse"`，给出原文行号
  `line` 与字符位置 `char`（均从 1 计），`tracks` 保留此前轨迹。
- 空行计入原文行号但不是有效行；尺码下标越界为 `"size_index"`，尺码列表
  非法为 `"sizes"`。
- 数字参数（起针数、起针序号）接受数字或纯数字字符串。

### 多尺码对称花样排针 `POST /api/pattern-layout`

为全部尺码选择**严格递增**的单侧花样重复数。每侧使用相同且至少一次的完整
花样重复：

```text
起针数   = 2×边针 + 中央针 + 2×花样宽度×单侧重复数
实际片幅 = 起针数 × 10 ÷ 每10厘米针数
```

请求体 JSON：

| 字段 | 含义 |
| ---- | ---- |
| `gauge` | 每 10 厘米针数（正数） |
| `sizes` | 尺码列表 `[{"name", "target"}]`，`target` 为目标片幅（厘米，正数），必须按**从小到大**排列 |
| `edge` | 单侧边针数（非负整数） |
| `center` | 中央针数（非负整数） |
| `pattern_width` | 花样宽度（正整数，针） |
| `tolerance` | 允许宽差（厘米，非负） |

```json
{
  "gauge": 22,
  "sizes": [
    {"name": "S", "target": 41},
    {"name": "M", "target": 48},
    {"name": "L", "target": 55}
  ],
  "edge": 2,
  "center": 6,
  "pattern_width": 8,
  "tolerance": 1
}
```

成功响应（各尺码实际片幅与目标差均不超过允许宽差，宽差绝对值之和最小，
同分取按尺码顺序字典序最小的重复数组）：

```json
{
  "ok": true,
  "base": 10,
  "step": 16,
  "total_deviation": 0.73,
  "sizes": [
    {"index": 0, "name": "S", "target": 41.0, "repeats": 5,
     "cast_on": 90, "width": 40.91, "deviation": 0.09},
    {"index": 1, "name": "M", "target": 48.0, "repeats": 6,
     "cast_on": 106, "width": 48.18, "deviation": 0.18},
    {"index": 2, "name": "L", "target": 55.0, "repeats": 7,
     "cast_on": 122, "width": 55.45, "deviation": 0.45}
  ]
}
```

- `base` 为固定针数（2×边针＋中央针），`step` 为单侧重复数每 +1 增加的起
  针数（2×花样宽度）。
- `repeats` 为各尺码选中的单侧重复数（≥ 1 且严格递增）；`width` 为按针数
  与密度换算的实际片幅，`deviation` 为 `|width − target|`；
  `total_deviation` 为各尺码偏差之和（以上厘米值均保留两位小数，寻优与
  比较全程用分数精确计算）。
- 数值字段接受数字或纯数字字符串；布尔值、负数（`gauge`/`target` 还须大于
  0）与无法解析的内容会被拒绝，`error.type` 为 `"params"`（标量参数）或
  `"sizes"`（尺码列表，含目标片幅未按从小到大排列）。

无可行组合时返回 `error.type` 为 `"infeasible"`，`message` 说明无法同时
满足约束，`sizes` 列出各尺码在允许宽差内的可行重复数范围
（`min_repeats > max_repeats` 表示该尺码单独即无可行重复数），
`fail_index` 为首个无法满足的尺码下标：

```json
{
  "ok": false,
  "error": {"type": "infeasible",
            "message": "无法同时满足约束：尺码 L 在允许宽差内单侧重复数只能取 3~3，但为满足各尺码严格递增，它至少需要取 4"},
  "base": 0,
  "step": 10,
  "fail_index": 2,
  "sizes": [
    {"index": 0, "name": "S", "target": 20.0, "min_repeats": 2, "max_repeats": 2},
    {"index": 1, "name": "M", "target": 25.0, "min_repeats": 2, "max_repeats": 3},
    {"index": 2, "name": "L", "target": 30.0, "min_repeats": 3, "max_repeats": 3}
  ]
}
```

### 对称减针行程 `POST /api/shaping-plan`

逐行安排左右相同的减针数：减针行之间至少隔一行平织，末行余针恰好等于目标
针数。在满足约束的方案中**最小化各行累计减针数与线性目标进度**（总减针数
×行号÷总行数）**的平方偏差之和**，同分取逐行单侧减针数组字典序最小的方案；
求解用动态规划，代价与比较全程分数精确计算。

请求体 JSON：

| 字段 | 含义 |
| ---- | ---- |
| `cast_on` | 起针数（正整数） |
| `target` | 目标针数，即末行余针（正整数） |
| `rows` | 总行数（正整数） |
| `max_decrease` | 每个减针行单侧最多减针数（`1` 或 `2`） |

```json
{"cast_on": 70, "target": 40, "rows": 15, "max_decrease": 2}
```

成功响应（`plan` 逐行给出左右减针数、本行共减、累计减针、行末余针与线性
目标进度）：

```json
{
  "ok": true,
  "cast_on": 70,
  "target": 40,
  "rows": 15,
  "max_decrease": 2,
  "total_decrease": 30,
  "per_side": 15,
  "decrease_rows": 8,
  "cost": 28.0,
  "plan": [
    {"row": 1, "left": 1, "right": 1, "decrease": 2, "decreased": 2,
     "remaining": 68, "progress": 2.0},
    {"row": 2, "left": 0, "right": 0, "decrease": 0, "decreased": 2,
     "remaining": 68, "progress": 4.0},
    {"row": 3, "left": 2, "right": 2, "decrease": 4, "decreased": 6,
     "remaining": 64, "progress": 6.0}
  ]
}
```

- `total_decrease` 为需减总针数（双侧合计，`cast_on − target`），`per_side`
  为单侧减针数，`decrease_rows` 为减针行数量。
- `cost` 为最小平方偏差和（保留四位小数）；`plan[].progress` 为该行末的
  线性目标进度（保留两位小数）；`plan[].remaining` 为行末余针，末行必等于
  `target`。
- 数值字段接受数字或纯数字字符串；布尔值、负数、非整数与无法解析的内容
  会被拒绝，`error.type` 为 `"params"`（`max_decrease` 只接受 `1` 或 `2`）。

无解时返回 `error.type` 为 `"infeasible"`，`message` 说明原因，
`max_total_decrease` 为约束下最多可减针数（双侧合计），
`max_decrease_rows` 为最多减针行数（`⌈rows/2⌉`）：

```json
{
  "ok": false,
  "error": {"type": "infeasible",
            "message": "需要共减 16 针（单侧 8 针），但 3 行内减针行两两至少隔一行平织，最多 2 个减针行、每行单侧最多 1 针，最多可减 4 针，还差 12 针"},
  "cast_on": 20,
  "target": 4,
  "rows": 3,
  "max_decrease": 1,
  "total_decrease": 16,
  "max_decrease_rows": 2,
  "max_total_decrease": 4
}
```

无解原因有三种：目标针数比起针数多（只能减针、无法加针）；起针数与目标
针数之差为奇数（左右对称减针每次共减偶数针）；行数不够（减针行两两至少
隔一行平织，最多 `⌈rows/2⌉` 个减针行，每行单侧最多 `max_decrease` 针）。

### 条纹用线排程 `POST /api/stripe-schedule`

求**恰好覆盖总行数**的连续异色条纹段：每段长度在 `[min_len, max_len]`
（1~6）内、相邻段异色、各色用量不超过库存；在可行方案中**最小化各段长度与
偏好段长的绝对差之和**（`Σ |段长 − preferred|`），同分逐段按颜色输入顺序
（编号小者优先）、再按段长升序选择（即 `(颜色编号, 段长)` 段序列字典序最小）。
求解用分层动态规划（整数精确计算）。

请求体 JSON：

| 字段 | 含义 |
| ---- | ---- |
| `total_rows` | 总行数（整数，1~40） |
| `colors` | 颜色列表 `[{"name", "stock"}]`，2~3 个；`name` 为非空且互不重复的颜色名，`stock` 为可编织行数/库存（正整数），列表顺序即颜色输入顺序 |
| `min_len` | 最短条纹行数（整数，1~6） |
| `max_len` | 最长条纹行数（整数，1~6，且 `min_len ≤ max_len`） |
| `preferred` | 偏好段长（正整数，通常取 `min_len~max_len`） |

```json
{
  "total_rows": 12,
  "colors": [
    {"name": "红", "stock": 6},
    {"name": "蓝", "stock": 5},
    {"name": "绿", "stock": 3}
  ],
  "min_len": 2,
  "max_len": 6,
  "preferred": 4
}
```

成功响应：`segments` 逐段给出颜色（`color_index` 为输入顺序下标）、本段
用量与从 1 计的起止行（首尾相接、末段 `end_row` 恰为 `total_rows`）；
`colors` 给出各色库存 `stock`、实际用量 `used` 与余量 `remaining`；
`cost` 为最小绝对差之和。

```json
{
  "ok": true,
  "total_rows": 12,
  "min_len": 2,
  "max_len": 6,
  "preferred": 4,
  "num_segments": 3,
  "cost": 2,
  "segments": [
    {"index": 1, "color_index": 0, "color": "红", "length": 4,
     "start_row": 1, "end_row": 4},
    {"index": 2, "color_index": 1, "color": "蓝", "length": 5,
     "start_row": 5, "end_row": 9},
    {"index": 3, "color_index": 2, "color": "绿", "length": 3,
     "start_row": 10, "end_row": 12}
  ],
  "colors": [
    {"index": 0, "name": "红", "stock": 6, "used": 4, "remaining": 2},
    {"index": 1, "name": "蓝", "stock": 5, "used": 5, "remaining": 0},
    {"index": 2, "name": "绿", "stock": 3, "used": 3, "remaining": 0}
  ]
}
```

- 数值字段接受数字或纯数字字符串；布尔值、小数、非整数与无法解析的内容会被
  拒绝，`error.type` 为 `"params"`（标量参数）或 `"colors"`（颜色列表，
  含数量不是 2~3 种、名称为空/重复、库存非正整数）。
- 无解时返回 `error.type` 为 `"infeasible"`，响应**不含 `segments`/
  `colors` 结果，即不返回部分安排**。库存合计少于总行数与“约束下无法恰好
  凑成总行数”由 `message` 区分：

```json
{
  "ok": false,
  "error": {"type": "infeasible",
            "message": "无法排程：2 种颜色的可编织行数合计仅 11 行，少于总行数 12 行，各色用量不超库存时无法覆盖全部行（不返回部分安排）"},
  "total_rows": 12,
  "min_len": 2,
  "max_len": 6,
  "preferred": 4
}
```
